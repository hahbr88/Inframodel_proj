# 애플리케이션 서버 구축

## 개요

본 문서는 레거시 온프레미스 환경의 애플리케이션 서버(legacy-app-01) 구축 절차를 정의한다.

애플리케이션 서버는 웹 서버로부터 전달받은 요청을 처리하며 데이터베이스 서버와 연동하여 서비스를 제공한다.

본 환경에서는 FastAPI 기반 애플리케이션 서비스를 운영한다.

---

# 서버 정보

| 항목     | 설정값                    |
| -------- | ------------------------- |
| 서버명   | legacy-app-01             |
| 역할     | Application Server        |
| 운영체제 | Ubuntu Server 24.04.4 LTS |
| CPU      | 2 Core                    |
| Memory   | 4 GB                      |
| Storage  | 30 GB                     |
| IP 주소  | 192.168.100.20/24         |

# 서버 상태 확인

서버에 접속 후 서버 정보를 확인한다.

```bash
hostnamectl
```

확인 결과 서버명이 아래와 같이 표시되어야 한다.

```text
legacy-app-01
```

IP 주소를 확인한다.

```bash
ip addr
```

# 패키지 업데이트

패키지 저장소 정보를 최신 상태로 갱신한다.

```bash
sudo apt update
```

설치된 패키지를 최신 상태로 업데이트한다.

```bash
sudo apt upgrade -y
```

배포 방식은 프로젝트 산출물 기준에 따라 진행한다.

예시

```bash
ls
```

# 서비스 포트 확인

애플리케이션 서비스가 지정된 포트에서 수신 대기 중인지 확인한다.

```bash
ss -tulpen | grep ':3000'
```

포트 3000이 LISTEN 상태로 확인되어야 한다.

---

# 웹 서버 연동 확인

웹 서버에서 애플리케이션 서버로 네트워크 통신이 가능한지 확인한다.

웹 서버에서 아래 명령어를 실행한다.

```bash
ping -c 4 192.168.100.20
```

정상적으로 응답이 반환되어야 한다.

애플리케이션 서비스가 HTTP 요청을 정상 처리하는지 확인한다.

확인 방법은 프로젝트 산출물 기준 엔드포인트를 사용한다.

예시

```bash
curl http://192.168.100.20:3000
```

정상 응답이 반환되어야 한다.

# 데이터베이스 서버 연동 준비

애플리케이션 서버는 데이터베이스 서버와 통신할 수 있어야 한다.

데이터베이스 서버 IP는 다음과 같다.

```text
192.168.100.30
```

실제 데이터 조회 및 저장 기능 검증은 데이터베이스 서버 구축 완료 후 진행한다.

---

# Reverse Proxy 연동 준비

웹 서버의 Nginx Reverse Proxy는 애플리케이션 서버로 요청을 전달한다.

서비스 구조는 다음과 같다.

```text
Internet
    │
    ▼
legacy-web-01
(Nginx)
    │
    ▼
legacy-app-01
(FastAPI)
```

애플리케이션 서버는 웹 서버의 요청을 받을 수 있도록 3000/TCP 포트에서 정상적으로 수신 대기 상태여야 한다.

Nginx Reverse Proxy 설정 및 전체 연동 검증은 모든 서버 구축 완료 후 진행한다.
